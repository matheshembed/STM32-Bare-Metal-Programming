Conceptual Doubts
	1. How The START and STOP Conditions are generated by the master ?
		➤ START Condition 
			Definition: A HIGH → LOW transition on SDA while SCL is HIGH.
			Meaning: “I’m taking control of the bus; everyone listen!”
			Effect: All slave devices detect this pattern and get ready to receive an address.
			🧠 Think of it as:“When clock (SCL) is high, and data line (SDA) suddenly falls → START condition.”

		➤ STOP Condition 
			Definition: A LOW → HIGH transition on SDA while SCL is HIGH.
			Meaning: “I’m done; bus is free now.”
			Effect: All devices know communication ended.
			🧠 Think of it as:“When clock (SCL) is high, and data line (SDA) rises → STOP condition.”

12C Registers and Programming Doubts
Line 111:
	1. What is open drain ? and why I2C requires Open drain ? and what if we not set this ?
		An open-drain (OD) output means the pin can only pull the line LOW, never HIGH.
		When it wants to represent logic ‘1’, it simply lets go of the line (leaves it floating).
		The line goes HIGH because of an external pull-up resistor.
		So:
		To send ‘0’ → transistor ON → SDA pulled LOW
		To send ‘1’ → transistor OFF → SDA floats → pulled HIGH by resistor.
		
		💡 Why I²C uses Open Drain?
			Because multiple devices share the same bus (SDA & SCL).
			If any device pulled it HIGH while another pulled it LOW → short circuit 💥
			Open drain avoids this conflict:
			If any one device pulls LOW → bus LOW.
			If all release → bus HIGH (via pull-up).
			This allows safe multi-master and multi-slave communication.
		
		⚠️ What if we don’t set it as open-drain?
			If we configure it as push-pull, both HIGH and LOW are driven actively by transistors.
			→ When two devices send opposite levels → bus contention, possible hardware damage.
			So I²C must always be open-drain (OD type).
		
***********************************************************************************************************************************			
Line 116:
	2. Why pull up is required ? and why not is pulled down //by default?
		Because with open-drain, no device can drive HIGH — so we need pull-up resistors to bring lines to logic HIGH when released.
		If we used pull-down:
		Line would rest LOW by default.
		Devices can only pull LOW (already LOW) — communication impossible!
		Hence:
		Pull-ups define the idle HIGH state of SDA & SCL.
		Without them, bus stays undefined (floating → random noise).
************************************************************************************************************************************		
Line 127:
	3. Why Entering and Exiting from the Reset mode is required ? What is the necessity ? and What if not ?
		I2C_SWRST bit (software reset) ensures:
		The entire I²C peripheral state machine resets.
		Clears previous errors or locked states.	
		Reinitializes all internal logic.
		This is recommended before any reconfiguration to ensure a clean state.

	⚠️ What if not done?
		If the peripheral was previously used or in an error/busy state:
		It might remain stuck in BUSY mode.
		Register writes may be ignored.
		Peripheral won’t start correctly.
		so always do 
			I2C1->CR1 |= I2C_SWRST;
			I2C1->CR1 &= ~I2C_SWRST;
**********************************************************************************************************************************

		I²C then derives its own SCL frequency from it using the CCR register.

	7. What BUSY actually means ? ... Does it using the bus or it is transferring or it is configuring ??
		SR2_BUSY = 1 → Bus is currently engaged in a communication.
		It means:
		SDA or SCL line is not both HIGH.
		Some device (master or slave) is currently transmitting/receiving.
		So:
		Not BUSY → bus idle, you can generate a START.
		BUSY → bus in use (another master or ongoing transaction).
		It does not mean “configuring”; it means actively used

Line 167:
	8. Why the address is shifted by 1 bit in the data register ?
		I2C Uses 7 bit addressing , but the 8th bit is R/W bit
		Format:
			|7-bit Slave Addr|R/W|
		So before writing:
			I2C1->DR = (saddr << 1);        // Write
			I2C1->DR = (saddr << 1) | 1;    // Read
************************************************************************************************************************			
Line 173:
	9. Why we have to clear the flag ? .. And if we assign it to a variable will it clear ?
		Some flags like ADDR are cleared by a read sequence , Not by writing 0
		From Reference Manual:	
			To clear ADDR, read SR1 followed by SR2
		This special read sequence resets the hardware logic that latches ADDR
		That is why:
			temp = I2C1->SR2;
		Is used only to trigger that read-clear mechanism.
		If not done ... Stuck waiting forever for the next event.
************************************************************************************************************************			
Line 188:
	10. Why it is OR'ed and Shifted ?
		I2C1->DR = saddr << 1 | 1;
		You left shift (to align with 7-bit format) and OR with 1 for the R/W bit.
			| 0 → Write
			| 1 → Read
		So this line means “send slave address + read bit”.

Line 194:
	11: Why we disabling the ACK ? .. What if we dont ? .. Why it is required ?
		When reading multiple bytes, master sends ACK after each byte to say "I want More"
		But before the lasy byte, master must SEND NACK to tell the slave "im done"
		
		To send NACK:(Not acknowledged)
			I2C1->CR1 &= ~CR1_ACK;
		If you dont disable ACK:
			Slave keeps sending more bytes	
			STOP Condition might be ignored
			Bus can get stuck waiting for next data
		So disabling ACK before lasy byte ensures a proper STOP
************************************************************************************************************************

	12. Why post incrementing ?
		*data++ means:
			Store received byte into current memory location.
			Then increment the pointer to the next byte.
			So if you’re reading N bytes:
				*data++ = I2C1->DR;
		Each new received byte gets stored sequentially in memory buffer.
		Post increment meaning:
			store → move to next location.
