What is Tightly Coupled Memory (TCM)?
    TCM is a very high-speed on-chip memory that is directly connected to the CPU core (not through the system bus or cache).
    It’s SRAM-based, like normal internal RAM,
    But it bypasses caches and the bus interconnect — it’s “tightly coupled” (i.e., hard-wired) to the CPU pipeline.
    Think of it like a private high-speed storage that the CPU can access in deterministic time (constant cycles, no cache misses, no bus contention).

Where it is located ?
    TCM is physically located inside the CPU core block, not in the general bus system.
    For example, in ARM Cortex-M7 (like STM32F7 or H7 series), you’ll find:
    ITCM = Instruction Tightly Coupled Memory (for code)
    DTCM = Data Tightly Coupled Memory (for data)
    These connect directly to the instruction and data ports of the core — skipping AHB/AXI buses entirely.

| Feature         | TCM                                 | SRAM (normal)                  | DRAM              | Cache                                  |
| --------------- | ----------------------------------- | ------------------------------ | ----------------- | ------------------------------------------ |
| Type        | SRAM                                | SRAM                           | DRAM              | SRAM                                       |
| Location    | Inside CPU core                     | On-chip, connected via AHB/AXI | Off-chip          | Inside CPU core                            |
| Access path | Direct, via dedicated port          | Through system bus             | External bus      | Internal hardware-managed                  |
| Speed       | Same speed as CPU clock             | Slightly slower (bus delay)    | Much slower       | Very fast (but non-deterministic)          |
| Access type | Deterministic (fixed cycles)        | Bus-latency dependent          | Very variable     | Non-deterministic (depends on hits/misses) |
| Managed by  | Software (you choose what to place) | Software                       | Software/Hardware | Hardware (automatic)                       |
| Refresh     | ❌ No                                | ❌ No                        | ✅ Yes            | ❌ No                                     |

🧰 Use cases of TCM

    Real-time and deterministic code execution
    When you need exact timing (e.g., interrupt handlers, motor control, flight control loops).
    → Place your critical ISR or control code in ITCM.
    Low-latency data access
    For data buffers that need to be accessed in exact cycles (e.g., audio processing, DMA targets).
    → Place those buffers in DTCM.
    When cache unpredictability is a problem
    Cache improves average performance but introduces non-deterministic timing (cache misses).
    TCM gives consistent timing, even if slightly smaller.

| Memory    | Speed                     | Predictability                   | Typical Size        | Managed by | Common use                   |
| --------- | ------------------------  | -------------------------------- | ------------------- | ---------- | ---------------------------- |
| Cache | 🔥 Fastest (1–2 cycles)      | ❌ Non-deterministic              | Tens of KB          | Hardware   | General performance          |
| TCM   | ⚡ Very fast (few cycles)    | ✅ Deterministic                  | Tens–hundreds of KB | Software   | Real-time critical code/data |
| SRAM  | 🚀 Fast                      | ✅ Mostly deterministic           | Hundreds of KB      | Software   | Normal variables, stack      |
| DRAM  | 🐢 Slow                      | ❌ Variable (refresh, bus delays) | MB–GB               | Software   | Large memory storage         |
